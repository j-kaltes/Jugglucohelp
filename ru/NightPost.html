Загрузка на сервер Nightscout

В большинстве случаев можно также использовать веб-сервер в Juggluco или juggluco-server. Только нескольким приложениям, которые лишь отображают веб-страницу Nightscout, нужен cgm-remote-monitor. Даже AAPS и AAPSClient можно использовать с веб-сервером Juggluco 7.4.1.

Все потоковые значения загружаются на сервер Nightscout по мере поступления. Если используется несколько датчиков, загружаются все значения каждого датчика. Некоторые приложения, циферблаты и виджеты Garmin предполагают, что значения идут с интервалом 5 минут. Получая значения каждую минуту, они показывают только последнюю пятую часть кривой. Поэтому встроенный в Juggluco веб-сервер разносит значения на 5 минут, кроме случаев, когда interval=secs задан меньшим значением.

URL: URL должен иметь вид https://hostname:port, например https://myname.herokuapp.com:6789.

Активно: включить загрузчик.

test V3: использовать api/v3 для загрузки в Nightscout. Не используйте это для сервера Nightscout, который раньше получал загрузки V1, и не отправляйте загрузки V1 на сервер, который раньше получал V3. Вместо api_secret нужно указать Access Token с разрешением загружать treatments и entries. Его можно создать в веб-интерфейсе Nightscout в Admin Tools. Это называется test, потому что другого загрузчика V3 не существует. Обычно используется V1.

Давать значения: также отправлять количества в Nightscout как treatments. При касании флажка открывается диалог, где для каждой метки можно указать, что она означает в Nightscout. Эти спецификации общие с веб-сервером в Juggluco (Левое меню→Настройки→Обмен данными→Веб-сервер). Отметить Давать значения можно только когда обработаны все метки. Если позже добавить новую метку, нужно не забыть указать, что с ней делать. Из-за ошибки в Nightscout вставки в более старые периоды или удаления показываются только после добавления элементов с новым временем. Поэтому лучше отправлять данные в Nightscout реже. Сейчас это выполняется каждый раз, когда пользователь уходит из Juggluco: выключает экран или переключается в другое приложение.

Отправить данные заново: загрузить все данные на сервер Nightscout повторно.

Отправить сейчас: обычно данные отправляются сразу, когда приходят от датчика или зеркального соединения. Нажмите эту кнопку, если предыдущая попытка по какой-то причине не удалась.

Версия Juggluco для Wear OS 4.15.0 и выше также может загружать значения глюкозы в Nightscout. Почти во всех случаях лучше отправлять их через Juggluco на телефоне или планшете либо через сервер Juggluco на компьютере. Это расходует батарею, особенно если сервер Nightscout недоступен, поэтому при ненадежном соединении лучше выключить Активно.

Ошибки

Два сообщения об ошибке часто вызывают путаницу.

Если сообщение выглядит как upload failure: и после двоеточия ничего нет, возможные причины:

  • сетевое соединение выключено;
  • имя хоста написано с ошибкой.

upload failure: java.io.FileNotFoundException: NIGHTSCOUTURL/api/v1/entries

Здесь NIGHTSCOUTURL означает URL сервера, введенный после «Nightscout URL».

Это вызывается одной из следующих причин:

  • URL указывает не на тот сайт. Например, после имени хоста отсутствует порт, поэтому Juggluco подключается к обычному веб-серверу;
  • api_secret указан неверно;
  • NIGHTSCOUTURL содержит путь, которого там быть не должно. Например, URL Nightscout — https://ahost.org:8887, а вы ввели https://ahost.org:8887/extra.
